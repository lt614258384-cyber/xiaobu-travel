# 小布的旅行：可靠性清理设计

## 目标

一次完成三个已知问题：用 FastAPI lifespan 管理定时器生命周期；让上传图片的文件名不再依赖中文档案名；从种子数据与已有数据库中清除“吉卜力动画风格”等旧风格词。

## 范围

### 1. 应用与定时器生命周期

- 使用 `asynccontextmanager` 定义 FastAPI lifespan，替代弃用的 `@app.on_event("startup")`。
- 启动时先初始化数据库，再创建并启动唯一的 `Scheduler` 实例。
- 将实例保存到 `app.state.scheduler`，避免实例只存在于局部变量中。
- 退出 lifespan 时调用调度器的 `shutdown()`；该方法应安全处理尚未运行或已经停止的情况。
- 保留现有首次生成和每日计划行为，不改变生成频率。

### 2. 上传文件名安全化

- 上传文件使用不可预测的 ASCII UUID 文件名，不再拼接用户输入的宠物名称或原始文件名。
- 仅保留小写的受支持图片扩展名：`.jpg`、`.jpeg`、`.png`、`.webp`；未知扩展名统一使用 `.jpg`。
- 数据库和网页仍保存标准的正斜杠相对路径，例如 `data/uploads/ref_<uuid>.jpg`。
- 保留现有最多 10 张参考照片和追加上传的行为。

### 3. Prompt 数据清理

- 从 `seed/activities_data.py` 的全部活动模板中移除“吉卜力动画风格”和伴随的旧固定风格后缀。
- 提供一个幂等的模板清理函数，清理标点和多余空白，重复运行不会继续改变结果。
- 应用启动时在数据库初始化之后清理已有 `Activity.prompt_template`，使旧 SQLite/PostgreSQL 数据无需手工重建。
- `Storyteller` 继续负责追加当前统一的半写实水彩风格，不再依赖运行时临时替换旧种子词。

## 数据流

启动流程为：创建表 → 清理已有活动模板 → 创建并启动 Scheduler → 提供服务。关闭流程为：停止 Scheduler → 退出应用。

上传流程为：读取原始扩展名 → 规范化/校验扩展名 → 生成 UUID 文件名 → 写入上传目录 → 保存 Web 相对路径。

## 错误处理

- lifespan 使用 `try/finally`，确保正常关闭或异常退出时都尝试停止调度器。
- 调度器关闭操作应幂等，不因未启动状态导致应用退出失败。
- Prompt 清理仅修改命中的模板；数据库操作失败时回滚并向启动流程抛出错误，避免以半清理状态继续运行。

## 测试策略

- lifespan 测试确认数据库初始化、模板清理、Scheduler 启动和退出关闭各发生一次。
- Scheduler 单元测试确认 `shutdown()` 在运行中和未运行时均安全。
- 上传测试使用中文宠物名与中文原始文件名，确认保存路径仅含 ASCII、安全扩展名且位于上传目录内。
- 种子数据测试遍历所有 203 条活动，确认不再包含旧风格词。
- 清理函数测试覆盖旧模板、重复执行和无需修改的模板。
- 最后运行完整 pytest 测试集，确认现有首页、档案、状态机、生成器与叙事行为没有回归。

## 非目标

- 本轮不引入 Alembic 或更改数据库结构。
- 不迁移现有上传文件，也不改写数据库中已经保存的旧图片路径。
- 不切换 Seedream 版本，不调整图片生成参数或角色一致性方案。
